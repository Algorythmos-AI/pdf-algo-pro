# Design-pass checklist

The lighter design pass that closes readiness blocker C5 for 1.0 (PAP-070): every screen state the app
ships, checked against the criteria below. Each cell links the snapshot or UI test that proves the
criterion, or says "owner check" when nothing automated does. C5 closes when the owner has walked
through a Release-configuration build against this checklist and dated every row
([readiness review](../readiness-review.md)). The pass reviews the screens as they are; the visual
refresh moved to 1.1 (PAP-070), so nothing here asks for a screen to look different.

Owner: Design · Reviewed: before each release candidate, and whenever a screen state is added

## How to use it

- The [snapshot gallery](gallery.md) shows every recorded snapshot side by side; open it beside this
  table. The previews linked in the first column show each state in Xcode's canvas, most of them
  also at the largest accessibility text size, in dark appearance and right to left.
- A linked UI test runs on every pull request's full CI run. Its accessibility audit
  (`performAccessibilityAudit()`, `UITestCase.audit`) fails on missing labels and traits, contrast,
  targets that are too small, and text that does not scale or is clipped, on the simulator in light
  appearance unless the cell says light and dark.
- "Owner check" is the owner's, on the walk-through below. A failure is an issue with the `design`
  or `accessibility` label naming the row and the criterion; the row is dated once it passes.
- A row is dated in "Owner reviewed (date)" when every one of its cells holds on the Release build,
  automated or not.

## Criteria

| Criterion | Passes when | Automated proof, where there is one |
|---|---|---|
| System components | Controls, lists, sheets, bars and alerts are the system's, styled only through the [design system](../design-system.md); nothing imitates a system control | None; owner check |
| Contrast | Text and controls read clearly in light, dark, and light and dark with Increase Contrast: 4.5:1 for text up to 17 points, 3:1 for larger text and controls ([design system](../design-system.md#accessibility)) | Snapshots in light and dark; the audit; token pairs in all four appearances in [`DesignSystemTests`](../../Packages/DesignSystem/Tests/DesignSystemTests/DesignSystemTests.swift) |
| AX5 text | At the largest accessibility size (AX5) nothing is clipped, overlaps or loses its meaning, and every action can still be reached | The selection bar at AX5; elsewhere the snapshots and UI tests run at AX3, so AX5 is an owner check |
| VoiceOver | Every control has a name and a role, decorative images are skipped, the order follows the screen, and the reader's rotors (headings, pages, annotations, citations) work | The audit for labels and traits; rotors and order follow the [VoiceOver script](../process/voiceover-script.md) |
| Voice Control | Every control can be named aloud by its visible label ("Tap Scan"); icon buttons answer to a short name | None; owner check |
| Reduce Motion | Nothing slides, zooms or loops that is not needed; the introduction's and the welcome's pictures hold still | None at screen level; owner check |
| Reduce Transparency | Glass and the brand glow turn opaque or go, and text over them stays readable | The brand glow, in [`DesignSystemTests`](../../Packages/DesignSystem/Tests/DesignSystemTests/DesignSystemTests.swift); the rest is an owner check |
| Right to left | Layout mirrors, chevrons and progress point the right way, and page order in the reader still follows the document | None; owner check, in the previews' right-to-left variants and in a Debug build with the right-to-left pseudolanguage (1.0 ships no right-to-left language) |
| French | Every string is translated, nothing is cut off, and French typography holds ([localisation](../process/localization.md)) | Every String Catalog entry has its French translation ([`untranslated.py`](../../scripts/ci/untranslated.py), in CI); the selection bar at AX5 in French |

## Walk-through of a Release build

The owner's part of the pass, about an hour on an iPhone. Results go in the table above and in an
issue per failure.

1. **Get a Release-configuration build.** Install the production build from TestFlight (Xcode Cloud's
   Release workflow, from `main`; [environments](../process/environments.md)), or run the app from
   Xcode on the iPhone with the scheme's Run action set to the Release configuration. Note the build
   number, the iPhone and the iOS version at the top of the issue that collects the results.
2. **Start clean.** Delete the app, install it again, and leave the iPhone's settings at their
   defaults: Large text, light appearance, English.
3. **Walk every row once as shipped.** First run to the offer, Close, Home; import the sample; open
   it and go through the reader's rows; scan a page and review it; ask, summarise, extract and explain
   a contract; open Settings, About, the privacy report; turn App Lock on, leave the app and come
   back. Mark "System components" for each row as you go, and note anything that looks broken or
   unlike the [gallery](gallery.md).
4. **Dark appearance.** Control Centre or Settings › Display & Brightness › Dark, then walk the rows
   again quickly for contrast.
5. **Increase Contrast.** Settings › Accessibility › Display & Text Size › Increase Contrast on, in
   light and then in dark appearance; check every row's contrast. Turn it off.
6. **Reduce Transparency and Reduce Motion.** Turn both on under Settings › Accessibility (Display &
   Text Size, and Motion). Walk first run, the offer, Home, and the reader's bars and sheets. The
   welcome after a purchase needs a purchase, so check it in its preview or on a Staging build. Turn
   both off.
7. **AX5.** Settings › Accessibility › Display & Text Size › Larger Text, on, slider to the end. Walk
   every row; every action must still be reachable by scrolling. Return to the default size.
8. **VoiceOver.** Follow the [VoiceOver script](../process/voiceover-script.md), which covers the
   rotors, and record its sign-off there as well.
9. **Voice Control.** Settings › Accessibility › Voice Control on. On each row say "Show names" and
   tap two or three controls by name, including an icon button. Turn it off.
10. **French.** Settings › General › Language & Region, French first (or Settings › PDF Algo Pro ›
    Language). Walk every row for truncation and translation. Switch back.
11. **Right to left.** Not on the Release build, which has no right-to-left language: in Xcode, run a
    Debug build with the scheme's App Language set to the Right-to-Left Pseudolanguage, or open the
    previews' right-to-left variants, and walk every row.
12. **Date the rows** that passed in "Owner reviewed (date)" and link the results issue from the
    readiness review's C5 row. When every row is dated, C5 closes.
