# 1.0 submission checklist

The go/no-go list for submitting PDF Algo Pro 1.0 to the App Store: one row per item, who owns it,
its status as the repository and GitHub show it, and the evidence. 1.0 is the scope of PAP-065 to
PAP-067 and PAP-070 in the [decision register](../decision-register.md): what is built, iPhone only,
every storefront, the visual refresh in 1.1. The policy is [release management](../release-management.md)
and the procedure the [App Store submission runbook](../process/runbooks/app-store-submission.md);
this page tracks the first submission against both. No prices, account details or private material
appear here (AGENTS.md rule 4).

Owner: Release · Reviewed: at every change of status before the 1.0 submission, then once after release

## How to read it

- **Owner.** "Agent" is work a coding agent does in a pull request; "Owner" is the maintainer's,
  because it needs the phone, App Store Connect, Xcode Cloud, a legal adviser or a product call.
- **Status.** "Done" has evidence in the repository or on GitHub; "Open" has none yet; "Partly"
  names what is missing. Nothing here is "Done" on a statement alone.
- **Go** needs every row Done, or deferred in the release pull request with a reason, as the
  [release pull request checklist](../release-management.md#the-release-pull-request) allows for
  issues only. A Critical blocker (C2, C5) cannot be deferred ([readiness review](../readiness-review.md)).

**Phased release on a first version.** Apple's page describes phasing a version *update* to people
who have automatic updates on ([Release a version update in phases](https://developer.apple.com/help/app-store-connect/update-your-app/release-a-version-update-in-phases)).
`Assumption:` 1.0, with no one yet to update, cannot be phased, and App Store Connect offers the
choice only from 1.0.1; checked on the version page in step 9 below. If so, 1.0 is released by hand
once approved, and its containment is the manual release and the kill-switch levers of
[release management](../release-management.md#rolling-back-on-ios), not phasing.

## Owner steps in App Store Connect for 1.0

In order. Names of pages and buttons follow Apple's help pages linked in each step; where Apple's
interface may differ, the step says what to look for. Values held privately (prices, the SKU,
contact details) come from the confidential editions and are typed by the owner only.

1. **Create the app record.** Apps › Add (+) › New App. Platform iOS; name "PDF Algo Pro: Scan,
   Sign, Edit"; primary language English (U.S.); the production bundle ID from
   [environments](../process/environments.md#summary); your own SKU; Full Access. Create. Read the
   App Store ID (the Apple ID under App Information) and give it to the agent for row 30.
2. **App Information.** Subtitle "Ask PDFs, get cited answers"; category Productivity, secondary
   Business; Content Rights; then Age Rating › Edit, and answer the questionnaire (row 19). Add the
   localisations from the language menu: English (Australia), English (U.K.), French (France),
   French (Canada), each with its name and subtitle from the [App Store strategy](../app-store-strategy.md#name-and-subtitle).
3. **App Privacy.** Privacy Policy URL; Get Started; answer "No, we do not collect data from this
   app"; Publish ([Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)).
4. **Pricing and Availability.** The app is free to download; Availability › all countries or
   regions (PAP-067).
5. **Trader status.** Declare trader status for the EU, as LR-19 advises, where Apple's
   [DSA page](https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements/)
   says; any contact shown is a company contact (V1-12).
6. **Subscriptions.** On the production app, follow the
   [subscriptions runbook](../process/runbooks/app-store-connect-subscriptions.md) steps 2 to 5 for
   Production, after Staging has passed: the group, Pro Yearly with its trial and Family Sharing,
   Pro Weekly without a trial, localisations, review notes, availability, and Billing Grace Period on.
   The review screenshot is taken from the Release build (step 8).
7. **Release build.** The production app has no Xcode Cloud product, so the build is archived on
   this Mac (PAP-072): in a clean checkout of the commit, `scripts/dev/release_archive.sh <commit>
   <build>`, then Xcode › Window › Organizer › Distribute App › App Store Connect, with symbols
   included and "Manage Version and Build Number" off. Add the build to the external group by hand
   ([environments](../process/environments.md#production-main)).
8. **External TestFlight.** When the release pull request has merged and the Release build has
   processed: TestFlight › External Testing › your external group › add the build; fill the Test
   Information; Submit for Review. Install it, take the subscription review screenshot (step 6), and
   keep it with testers for at least 3 days (row 28).
9. **The version page.** App Store › iOS App › 1.0.0. For each localisation: screenshots for the
   iPhone 6.9-inch display, promotional text, description, keywords, support URL, What's New if the
   field is offered ([What's New in 1.0](../app-store-strategy.md#whats-new-in-10)). Then: Build ›
   select the Release build; copyright; App Review Information › sign-in not required, contact
   details, Notes › paste the [review notes for 1.0](../app-store-strategy.md#review-notes-for-10);
   In-App Purchases and Subscriptions › add both plans; Version Release › Manually release this
   version; Phased release › on, if the page offers it (see the note above).
10. **Submit.** Add for Review › Submit to App Review
    ([Submit for review](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-for-review)).
11. **After approval.** Check that `main`'s head is the built commit and run the `release` workflow
    (row 32); then Release This Version. Watch crash reports, support email and reviews daily
    ([App Store submission runbook](../process/runbooks/app-store-submission.md), steps 11 to 13).
