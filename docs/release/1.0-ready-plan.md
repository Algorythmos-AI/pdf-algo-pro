## Context

1.0 is code-complete except for the queued fixes. What is left: getting about ten branches through a
macOS CI runner that takes one job at a time, five clean nightlies, the owner's device sign-offs,
App Store Connect setup, legal answers, a soak on external TestFlight, and App Review. This plan
puts all of that in one dated order, so the owner can take the steps day by day and the CI queue
never sits idle.

**Headline estimate.** Submission **Sat 2026-11-07**; Ready for Sale **Mon 2026-11-09**, with a
range of 11-09 to 11-16. With the batching below, CI is not what decides the date. The
**legal answers** and the **3-day external soak** are.

**How this plan gets a first-time App Review pass and a clean 1.0.** Three layers, each with a
hard stop:
1. **Bug zero** (section 2b). Nothing ships with an open p0, p1 or `release-blocker` bug. Every p2
   or p3 bug is either fixed or named as a known issue with the owner's sign-off. The release
   candidate (RC) passes the nightlies, the sanitizers, PDF validation, a device run, a device bug
   bash, a 30-minute device soak (WM:27) and 72 hours on external TestFlight without a new crash.
2. **Reviewer rehearsal** (section 5b). Before submitting, the owner and an agent run the exact
   review-notes path on the exact build being submitted. They do it from a clean install, on a
   phone *without* Apple Intelligence, on an iPad (compatibility mode) and in airplane mode,
   because App Review may use any of these. Each App Review guideline the app touches is checked
   against evidence.
3. **Contingencies** (section 6b). Every likely failure has a fixed response, so nothing waits
   for a fresh plan.

- Every merge into `integration` starts a push run (QG:102). Push runs are never cancelled
  (CI:78–81, `cancel-in-progress` only for `pull_request`). `Assumption:` GitHub keeps one pending
  run per concurrency group, so merges made close together collapse their push runs into one.

  input"). PR 359's run took 19 s, so docs PRs merge at any time.

  Its run then queues ahead of that merge's push run.

## 6b. Contingencies: if this happens, do that

| Trigger | Response | Date effect |
|---|---|---|

| A nightly fails after the RC | Owner decides: release-blocker → fix on `integration` → new RC builds → the device checks rerun in short form (smoke test, rehearsal) | +1–2 days before the release PR; +4 after it (new build, soak restarts) |
