# ADR-0013: GitHub Actions for gates, Xcode Cloud for signed builds

**Status:** accepted (2026-09-28)

**Context.** Pull requests need fast, reproducible gates; signed builds need Apple signing and App Store Connect access without storing signing keys in GitHub.

**Decision.** Exactly four GitHub Actions workflows: `ci.yml` (title, promotion guard, secret scan, docs, invariants, and iOS build/test/coverage behind a change detector), `codeql.yml`, `release.yml` (manual, on `main`), `dependency-review.yml`. Actions are pinned to commit SHAs; tools are pinned and checksum-verified. Xcode Cloud builds the Staging configuration from `integration` for TestFlight internal and the Release configuration from `main` for TestFlight external and the App Store. Build numbers come from `CI_BUILD_NUMBER`.

**Alternatives considered.** GitHub Actions for signing and upload (stores an App Store Connect key in GitHub). fastlane (third-party tooling the organisation does not use).

**Consequences.** No signing material in GitHub. Two CI systems to understand; the split is by purpose. iOS gates are dormant (reported as skipped) until code exists.

**Pillars served.** PIL-7

**References.** [Xcode Cloud](https://developer.apple.com/documentation/xcode/xcode-cloud) · [GitHub Actions security hardening](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions)

**Addendum (2026-09-30).** CodeQL for Swift builds the app under the CodeQL tracer, which takes 30–50
minutes on a GitHub macOS runner even for one architecture, and held runners that the required `ios`
check needed. It now runs nightly on `integration`, on demand, and on release pushes to `main` that
change Swift, instead of on every pull request. Swift findings arrive within a day of a merge; the
`codeql (actions)` analysis still runs on every pull request.
