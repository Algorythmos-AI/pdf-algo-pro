# Coding standards

The rules every line of PDF Algo Pro code follows, whatever the language: how the code is
structured, how it handles errors, what it may log, how it treats untrusted documents, how it is
localised and made accessible, how it stays fast, how it uses concurrency, when it may depend on
someone else's code, and how it is commented. Swift and SwiftUI idioms are in the
[Swift style guide](swift-style-guide.md); how the rules are checked in review is in the
[code review guide](code-review-guide.md). Where a gate enforces a rule, this document says so.

Owner: Architecture · Reviewed: each milestone, and whenever an ADR changes

| Coverage gate | [coverage_gate.py](../scripts/ci/coverage_gate.py), `ios` job | At least 80% line coverage overall and per first-party target ([ADR-0014](adr/0014-testing-strategy-and-coverage.md)) |

`project.yml` exist; proving them on the first code pull request is a readiness item

## Architecture rules

The structure is decided in [ADR-0002](adr/0002-xcodegen-and-modular-spm.md) and
[ADR-0003](adr/0003-swiftui-observation-and-di.md) and explained in the
[iOS architecture review](ios-architecture-review.md#swiftui-architecture). Code lives in local
Swift packages, one per capability, under a thin app target generated by XcodeGen.

### Allowed dependencies

Dependencies point towards `Core`. A package may import only the first-party packages in its row.

```
App ──► Features/* ──► DesignSystem ──► Core
 │          └────────► Core
 │          └────────► service packages, for their SwiftUI adapters and value types only
 └────► every service package (to compose AppContainer)

Service packages ──► Core          (Intelligence also ──► Search)
```

| Package | May import (first-party) | Responsibilities and permissions |
|---|---|---|
| App target | Every package | Scenes, `AppContainer` composition, the deep-link router, entitlements. No business logic. |
| `Features/<Name>` | `Core`, `DesignSystem`; a service package only for its SwiftUI adapter or value types (for example Reader uses `PDFEngine`'s page view) | Screens and `@Observable @MainActor` feature models. Never another feature package. |
| `DesignSystem` | `Core` | Tokens, components, the `Motion` helper. The only place colour literals may appear. |
| `DocumentStore` | `Core` | Coordinated file access, iCloud Drive, the SwiftData library index, CloudKit private-database sync |
| `PDFEngine` | `Core` | The only importer of the commercial PDF SDK; PDFKit contingency |
| `Scanning` | `Core` | VisionKit document camera adapter |
| `OCR` | `Core` | Vision text recognition |
| `Intelligence` | `Core`, `Search` | Foundation Models tiers, prompts, consent state. Network allowed. |
| `Search` | `Core` | Core Spotlight and the on-device index |
| `Commerce` | `Core` | StoreKit 2. Network allowed. |
| `Telemetry` | `Core` | MetricKit, signposts, allow-listed telemetry events. Network allowed. |
| `Core` | None | Domain value types, service protocols, `Route` values. Foundation only. |

### Rules

1. **No cycles, no upward imports.** A service package never imports a feature package, the design
   system or the app target.
2. **Features are independent.** A feature never imports another feature. Cross-feature navigation
   goes through `Route` values and the router ([ADR-0004](adr/0004-navigation-and-multi-window.md)).
3. **Depend on protocols.** Services are protocols in `Core`; features receive them through
   initialisers; live implementations are composed only in the app target.
4. **UIKit stays in adapters.** `UIViewRepresentable` and `UIViewControllerRepresentable` wrappers,
   in the package that owns the capability. This is the only cross-platform rule in V1
   ([platform strategy](platform-strategy.md)).
5. **Vendor types never cross the boundary.** `PDFEngine`'s public API uses our own `Sendable` value
   types; nothing outside it sees an SDK type ([ADR-0007](adr/0007-pdf-sdk-boundary-and-vendor-selection.md)).
6. **No singletons, no global mutable state.** The few Apple singletons (for example
   `UserDefaults.standard`) are wrapped behind a protocol.
7. **One way in.** Every external entry point (URL, App Intent, Spotlight, widget, control, Handoff)
   becomes a `Route` through the router; the router only navigates, and actions need explicit user
   intent.

### Automated by the invariants gate

[invariants.py](../scripts/ci/invariants.py) enforces these today:

| Rule | Active |
|---|---|
| A PDF may only be committed under `Tests/Fixtures/Synthetic/` | Always |
| No `try!` and no `as!` outside tests | Once Swift exists |
| `print(` only inside `#if DEBUG` | Once Swift exists |
| Networking APIs (`URLSession`, `URLRequest`, `NWConnection`, `WKWebView`, `import Network`) only in `Intelligence`, `Commerce` and `Telemetry` (tests exempt) | Once Swift exists |
| Colour literals (`Color(hex:`, `Color(red:`, `UIColor(red:`, six-digit hex) only in `DesignSystem` (tests included) | Once Swift exists |
| The commercial PDF SDK (`PSPDFKit`, `PSPDFKitUI`, `Nutrient`, `NutrientUI`, `PDFNet`, `Tools`) imported only in `PDFEngine` | Once Swift exists |
| A `PrivacyInfo.xcprivacy` exists and declares every required-reason API category the code uses (user defaults, file timestamps, system boot time, disk space) | Once Swift exists |

Because the SDK check matches `import Tools` (an Apryse module name), no first-party module may be
named `Tools`.

Package-to-package rules are declared in each `Package.swift`: SwiftPM rejects dependency cycles,
and its `--explicit-target-dependency-import-check` option can fail a build that imports an
undeclared module ([SwiftPM build options source](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/CoreCommands/Options.swift)).
CI does not use that option yet, because the `ios` job builds through Xcode.
Rules 2 to 7 above are checked in review. Moving rule 2 and the adapter rule into `invariants` (an
import allow-list per package) is proposed below.

## Error handling

### Decision: one error type per package, untyped `throws` at package boundaries

Each package defines its own error enumeration (`PDFEngineError`, `DocumentStoreError`, `OCRError`,
`IntelligenceError`, `SearchError`, `CommerceError`, `ScanningError`). Public functions use untyped
`throws`, document the error type in a `- Throws:` line, and guarantee that only that type escapes
(tested). Typed throws (`throws(PDFEngineError)`) are used inside a package where every case is
handled exhaustively.

- **Rationale.** The typed-throws proposal itself advises that untyped `throws` remains the better
  default for most code and reserves typed throws for code that stays within a module or package
  where the error is always handled ([SE-0413: Typed throws](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0413-typed-throws.md)).
  One named type per package still gives callers a closed, documented set to map to user messages.
- **Trade-offs.** The compiler does not enforce the documented type at the boundary; a test per
  public entry point does.
- **Alternatives considered.** Typed throws on every public API (hard to evolve, as SE-0413
  explains). One app-wide error type (couples every package to every failure). `Result` return
  values (duplicates what `throws` and `async` already express).
- **Risks.** A vendor or system error leaking through unwrapped: the boundary tests call each
  public entry point with failing fakes and assert the error type.
- **Future scalability impact.** Packages can change their internals, and a vendor can be replaced
  behind `PDFEngine`, without changing any caller's error handling.

### Rules

- No `try!` and no `as!` (automated); no force unwraps (`swift-format`). `fatalError` and
  `preconditionFailure` are for programmer errors only, with a message, and never on a path that a
  document, a file or the network can reach. A malformed PDF must never crash the app.
- `try?` only when failure genuinely does not matter, with a comment saying why. Otherwise handle,
  propagate or log the error.
- Errors carry context that is safe to log (codes, counts, hashed identifiers), never document
  content or file names.
- Cancellation is not a failure: `CancellationError` propagates silently and is never shown.
- Retries are bounded, only for idempotent operations, with back-off, and only in the packages that
  may use the network.

### User-facing error messages

Errors are turned into messages in the feature layer, from the package's error type, using strings
in the String Catalog. Messages follow the
[Human Interface Guidelines on alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)
and [writing](https://developer.apple.com/design/human-interface-guidelines/writing): say what
happened and what the person can do, in plain words, without blame, codes or jargon. Prefer an
inline message; use an alert only when the person must act now.

| Situation | Message | Actions |
|---|---|---|
| Wrong password for an encrypted PDF | "That password didn't open this PDF." | Try Again · Cancel |
| File in iCloud not downloaded, device offline | "This PDF is stored in iCloud and can't be downloaded while you're offline." | OK |
| Edited on another device at the same time | "This PDF was changed on another device." | Keep This Version · Keep Both |
| Damaged file | "This file can't be opened because it's damaged." | Choose Another File |

Never show a system or vendor `localizedDescription` directly: it can contain file paths or
internal detail.

## Logging

Logging uses `Logger` from the unified logging system, never `print` (automated outside
`#if DEBUG`), and never a third-party logger ([ADR-0012](adr/0012-on-device-observability.md)).

- **Subsystem and categories.** Subsystem `com.algorythmos.pdfalgopro` in every build configuration,
  so filters stay stable; one category per package (`App`, `Reader` and the other feature names,
  `DocumentStore`, `PDFEngine`, `Scanning`, `OCR`, `Intelligence`, `Search`, `Commerce`,
  `Telemetry`, `DesignSystem`). Apple recommends reverse-DNS subsystems and categories per component
  ([Generating log messages from your code](https://developer.apple.com/documentation/os/generating-log-messages-from-your-code)).
- **Levels.** `debug` for development detail; `info` for helpful but non-essential events;
  `notice` (the default) for state changes needed to troubleshoot; `error` for failures the app
  recovered from; `fault` for bugs and broken invariants. Debug and info messages stay in memory;
  notice and above are persisted (same source).
- **Privacy.** The system redacts dynamic strings and objects by default but not integers,
  floating-point values or Booleans (same source). So: never mark a value derived from a document
  or the user `privacy: .public`; use `.public` only for static identifiers, enumeration cases,
  error codes and durations; use `privacy: .private(mask: .hash)` when messages must be correlated
  to the same document without revealing it.
- **Never log**, even redacted: document text, OCR output, annotations, form values, signatures,
  file names or paths, search queries, prompts and model responses, clipboard contents, purchase
  receipts or transaction identifiers, account or device identifiers. Nothing classified
  confidential or restricted in [data classification](data-classification.md) reaches a log.
- **Signposts** use the same subsystem through `OSSignposter`; interval names are static strings
  that match the [performance budgets](performance-budgets.md) (see [performance](#performance)).
- **Telemetry is not logging.** Product telemetry goes only through the `Telemetry` package's
  allow-listed schema ([ADR-0017](adr/0017-privacy-first-telemetry.md),
  [analytics strategy](analytics-strategy.md)).

## Security

The threat model is in [threat model](threat-model.md); data handling in
[privacy architecture](privacy-architecture.md) and [data classification](data-classification.md).

- **No secrets in the repository.** No keys, tokens, certificates, provisioning profiles or the
  Apple Team ID; they are injected at build time ([ADR-0015](adr/0015-identifiers-and-signing.md)).
  The `secrets` gate scans every pull request, and `.gitignore` excludes signing material.
- **Documents are untrusted input.** Every PDF is parsed only through `PDFEngine`, which returns
  typed errors for malformed input, bounds work by time and memory, and is fuzzed
  ([testing strategy](testing-strategy.md#malformed-and-fuzzed-input)).
- **Active content stays inert.** JavaScript in a PDF is never executed; launch actions and embedded
  files never open automatically; a link opens only after the person sees and confirms the
  destination; remote resources referenced by a document are never fetched. How each is switched
  off in the chosen SDK is a vendor-spike criterion ([ADR-0007](adr/0007-pdf-sdk-boundary-and-vendor-selection.md)).
- **Deep links are untrusted.** A URL, intent or shared link can navigate, never act
  ([ADR-0004](adr/0004-navigation-and-multi-window.md)).
- **Document content is data, not instructions.** Prompts separate instructions from document text,
  models cannot trigger actions, and tool calls are read-only ([AI governance](ai-governance.md)).
- **Redaction removes content.** A redaction deletes the text, image data, vector content and
  metadata under the redacted area, rewrites the file without earlier revisions, and is verified by
  tests that search the output for the removed strings. A box drawn over text is an annotation, and
  the UI never calls it redaction ([testing strategy](testing-strategy.md#true-redaction-verification)).
- **Storage.** Documents use the data-protection class chosen in the architecture review; tokens
  live in the Keychain; cryptography uses Apple's frameworks (CryptoKit), never custom code.
- **Least privilege.** Every entitlement, permission prompt and network use is justified in the pull
  request and approved by the Security role ([code review guide](code-review-guide.md#approval-thresholds-by-role)).
- **Supply chain.** Dependencies are pinned in `Package.resolved` (the `ios` job fails on drift);
  GitHub Actions are pinned to commit SHAs with read-only default permissions; build tools are
  pinned and checksum-verified ([ci.yml](../.github/workflows/ci.yml)).

## Localisation

PDF Algo Pro launches in English and French and is right-to-left ready (the V1 milestone in
[milestones.yml](../.github/milestones.yml); [PRD](prd.md)).

- **String Catalogs only.** Every user-facing string lives in a String Catalog
  ([Localizing and varying text with a string catalog](https://developer.apple.com/documentation/xcode/localizing-and-varying-text-with-a-string-catalog)),
  with a translator comment that says where it appears. No user-facing literals outside catalogs.
- **Package bundles.** Packages declare a default localisation and look strings up in their own
  bundle (`#bundle` or `.module`); otherwise lookups go to the app's main bundle
  ([`#bundle`](https://developer.apple.com/documentation/foundation/bundle())).
- **No concatenated sentences.** Build a sentence as one localised string with placeholders, never
  by joining fragments or adding `Text` values together; word order differs between languages.
- **Plurals and variants** use the catalog's plural and device variants, never `count == 1` checks.
- **Formatters, not string building,** for dates, numbers, measurements, byte counts, lists and
  person names (Foundation `FormatStyle`s with the current locale).
- **Right-to-left ready.** Use leading and trailing, never left and right; mirror directional images;
  test with the right-to-left pseudolanguage ([HIG: right to left](https://developer.apple.com/design/human-interface-guidelines/right-to-left)).
  Document pages are never mirrored: a PDF renders as its author made it.
- **English and French together.** A feature is not done until its French strings are in the
  catalog (see the [Definition of Done](engineering-playbook.md#definition-of-done)).

## Accessibility by default

Accessibility is designed and tested with every feature, following the
[Human Interface Guidelines on accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility).

- **Text** uses Dynamic Type text styles, never fixed sizes, and reflows at every size up to the
  largest accessibility size instead of truncating. The HIG asks that text can be enlarged to at
  least 200% (same source).
- **Every control has a label** that VoiceOver and Voice Control can use; icon-only buttons are
  built from `Label` so the title is still there. Hints only when the label is not enough.
- **Targets** are at least 44 by 44 points on iPhone and iPad (same source).
- **Contrast** meets the HIG minimums: 4.5:1 for text up to 17 points, 3:1 for larger or bold text
  (same source, based on WCAG AA). Colours come from `DesignSystem` tokens with Increase Contrast
  variants; state is never shown by colour alone.
- **Motion** goes through the `Motion` helper, which honours Reduce Motion; transparency honours
  Reduce Transparency.
- **Structure**: related elements are grouped for VoiceOver; PDFs expose headings and pages through
  custom rotors; asynchronous results (OCR finished, an answer ready) are announced.
- **Keyboard**: every action is reachable from a hardware keyboard on iPad and Mac.
- **Tests**: every screen runs the automated accessibility audit, and a scripted VoiceOver pass runs
  before each release ([testing strategy](testing-strategy.md#accessibility-tests)).

## Performance

Budgets and their measurement are in [performance budgets](performance-budgets.md).

- **Never block the main actor.** File I/O, PDF parsing and rendering, OCR, model calls, hashing,
  image decoding and large JSON work run off the main actor. Apple's rough thresholds: main-thread
  work for a discrete interaction under 100 ms, and under one display refresh interval (8 or 17 ms)
  during continuous interaction ([Improving app responsiveness](https://developer.apple.com/documentation/xcode/improving-app-responsiveness)).
- **Signpost every budget.** Each row in the performance budgets has an `OSSignposter` interval
  with the same name; a new budgeted operation adds its signpost and performance test in the same
  pull request.
- **Large data never sits in observable state.** Pages render as tiles from the engine; thumbnails
  come from a cache; lists of documents are lazy with stable identities.
- **Launch does only what the first frame needs.** No network, indexing or migration work before the
  first frame; deferred work is scheduled, not started eagerly.
- **Background work** uses the system's task APIs, respects thermal state and Low Power Mode, and
  cancels cooperatively ([iOS architecture review](ios-architecture-review.md#background-processing)).
- **Measure, then optimise.** A `perf:` change shows numbers before and after, on the same device.

## Concurrency

Swift 6 language mode with strict concurrency `complete`, warnings as errors
([ADR-0001](adr/0001-platform-floor-and-swift-6.md)). The model is explained in
[The Swift Programming Language: Concurrency](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/)
and the [Swift 6 migration guide](https://www.swift.org/migration/documentation/swift-6-concurrency-migration-guide/dataracesafety).

- **Sendable boundaries.** Values that cross an isolation boundary are `Sendable` value types.
  `@unchecked Sendable` and `nonisolated(unsafe)` are allowed only in adapters that wrap a framework
  or SDK type, with a comment explaining the synchronisation and a test that exercises it.
- **Actors own shared mutable state**: document I/O, the OCR queue, indexing, AI sessions. Feature
  models are `@MainActor` and only orchestrate. No locks or dispatch queues in new code; where an
  actor is the wrong tool for a tiny critical section, use `Mutex` from the Synchronization module
  ([Mutex](https://developer.apple.com/documentation/synchronization/mutex)).
- **Structured concurrency first.** `async let` and task groups for parallel work, with a bound on
  concurrency (for example, a fixed number of OCR pages in flight). SwiftUI's `.task` modifiers for
  work tied to a view's lifetime. An unstructured `Task { }` only at a UI event boundary, stored and
  cancelled by its owner. `Task.detached` needs a comment explaining why.
- **Cancellation is cooperative.** Long loops check for cancellation per page or chunk; calls into
  frameworks that do not observe task cancellation are wrapped with a cancellation handler.
- **Reentrancy.** After every `await` inside an actor, re-check any state read before it.
- **No `DispatchQueue.main.async`**, and `MainActor.assumeIsolated` only in adapters where the
  framework documents that a callback runs on the main thread.
- **`@preconcurrency import`** only for a module not yet annotated for concurrency, with an issue to
  remove it.

## Dependencies

No third-party dependency without an ADR ([AGENTS.md](../AGENTS.md)); this includes test-only
libraries ([ADR-0018](adr/0018-snapshot-testing-test-only-dependency.md) is the precedent), build
tools and GitHub Actions.

The ADR answers: what it does and why an Apple framework or a small amount of our own code is not
enough; licence; privacy manifest; network and telemetry behaviour, audited rather than taken from
the vendor's word; binary size; Swift 6 readiness; platform coverage (iPhone, iPad, Mac, visionOS);
maintenance health and security record; and the exit plan. The same pull request adds a
[NOTICE](../NOTICE.md) entry. Versions are pinned in `Package.resolved`, the `dependency-review`
gate fails on newly added high-severity vulnerabilities, and Dependabot proposes updates (the Swift
ecosystem is added with the first `Package.swift`).

## Comments and documentation comments

- **Document every public declaration** with a `///` comment that starts with a one-line summary,
  as the [Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/)
  ask; parameters, return values and thrown errors are documented, and `swift-format` checks it.
- **Comments explain why**, not what: the constraint, the Apple or vendor behaviour being worked
  around (with a link), the reason for an unusual choice.
- **`TODO` needs an issue**: `// TODO(#123): …`. No commented-out code; git keeps history.
- **Link sources**: a workaround for a framework bug cites the feedback or documentation it relies on.
- **Prose spelling** in comments and documentation is Australian/British, like the rest of the
  documentation; identifiers follow the [naming rules](swift-style-guide.md#naming).

## Scripts and workflows

- CI scripts are Python 3 with the standard library only, as the existing gates are; shell scripts
  start with `set -euo pipefail`.
- Workflows keep read-only default permissions, SHA-pinned actions and a timeout on every job, and
  stay within the four workflow files ([ADR-0013](adr/0013-ci-cd.md)).
- A new gate runs locally with the same command CI uses, so nobody discovers a rule only in CI.
